# Environment variables

Set serving variables before starting `enginesrv`, unless an entry says otherwise. Some are read per call or at engine or session creation.
The API key variable is not listed here: its name comes from `api_key_env` in the [configuration file](configuration.md).

Two kinds of values appear below:

- A **switch** that is unset keeps its default. A switch that is set is on only for `1`, `true` or `on` (surrounding spaces and letter case are ignored); any other value turns it off.
- A variable with **accepted values** refuses startup when set to anything else, unless the table says otherwise.

## Build

| Variable | Default | Meaning |
| --- | --- | --- |
| `INFERENCE_CUDA_ARCHS` | `75,86,89` (`72` on aarch64) | GPU architecture targets of the CUDA kernels, read by `cargo build --features native-cuda`. The default covers RTX 20, 30 and 40 series; a single target such as `86` builds faster and smaller. The build also includes PTX for the highest target, which a newer driver may compile for a newer GPU; PTX does not run on an older architecture. A native `120` target for RTX 50 series needs CUDA 12.8 or newer. A target that builds is not thereby qualified. See [CUDA FP16 prefill attention](configuration.md#cuda-fp16-prefill-attention). |
| `FIFI_CUDA_LINEINFO` | unset (off) | Adds `-lineinfo` to the `nvcc` flags of a `cargo build --features native-cuda`, embedding source line information in the kernels without changing optimization. Set it for builds whose kernels are examined with `compute-sanitizer` (for example `compute-sanitizer --tool memcheck`) or an NVIDIA profiler, so their reports name kernel source lines; leave it unset otherwise so standard builds keep their usual artifacts. Read at build time; only the on-words arm it, so `0` stays off; rebuild to change. |
| `FIFI_CUDA_ATTN_PREFILL_TURING` | off | Set to `1` and prefill attention takes the typed half-precision Turing pilot arm; any other value keeps the established accumulation path. The pilot is for sm75 devices and is not device-qualified. Read once per process. |

NVIDIA documents the [GPU compute capabilities](https://developer.nvidia.com/cuda/gpus), [PTX compatibility rules](https://docs.nvidia.com/cuda/archive/12.8.1/blackwell-compatibility-guide/index.html), and [CUDA 12.8 compiler support for SM 120](https://docs.nvidia.com/cuda/archive/12.8.2/cuda-features-archive/index.html).

## Server

| Variable | Default | Meaning |
| --- | --- | --- |
| `FIFI_CPU_GREEDY_BLOCKS` | off | Set to `1` to scan host logits in 256-value blocks for greedy sampling. Other values use the scalar scan. Both select the first maximum and reject non-finite logits. Applies to host rows of at least 256 values. Restart the process to change the setting. The contributor's measured draw-cost figure (0.20 to 0.03 ms) is not verified on our hosts. |
| `FIFI_CPU_Q8G_F16C` | off | Set to `1` and the AVX2 CPU expert routine runs its inner dot product in half precision through F16C when the CPU carries the feature; any other value keeps the reference path. Read once per run. |
| `ENGINESRV_WARM_TURNS` | on (switch) | With `prefix_reuse`, remember the last conversation's tokens so that the next turn only tokenizes its new messages. A request from another conversation replaces the memory. |
| `ENGINESRV_SEED_RESENDS` | on (switch) | With warm turns on, keeps the token IDs of a freshly rendered prompt, so that an identical retry skips rendering and tokenization. Measured with the Qwen3.6 tokenizer on a 256,855-token conversation: a retry took 1.0 to 1.2 ms with the seed and 270 to 310 ms without it. The startup line `seeded retries:` states the mode. Restart to change. |
| `ENGINESRV_RESEND_EXTRA_BYTES` | `0` | With seeded resends enabled, retain one displaced conversation’s completed token result if its allocation fits this per-engine byte budget. An exact retry can reuse it until the next reseed. |
| `ENGINESRV_PREFIX_BLOCK_MATCH` | on (switch) | With `prefix_reuse`, also save one block checkpoint, cut at a multiple of `ENGINESRV_PREFIX_BLOCK_TOKENS` tokens just before the end of the conversation, so a prompt that changes only near its end can still reuse most of it. Used by engines that keep at least two saved prefixes. |
| `ENGINESRV_PREFIX_BLOCK_TOKENS` | 4,096 | Spacing of the cut points, in tokens. Values below 1 select the default. |
| `ENGINESRV_CACHE_USAGE` | on | Report reused prompt tokens in the API usage fields. Once set, only the exact values `1`, `true` and `on` keep it on. |
| `ENGINESRV_THINK_REPLAY` | on (switch) | Qwen3.6 only: keep the reasoning that clients resend with earlier assistant turns in the prompt. Off removes it for every engine. |
| `ENGINESRV_NOTICE_TOOLWRAP` | on (switch) | Qwen3.6 only, with think replay on: render system messages that follow an assistant turn as tool responses, so that the chat template keeps the reasoning of earlier tool-calling turns. |
| `ENGINESRV_SHADOW_BLOCK_LCP` | off (switch) | Read-only observation for the request log: report the longest common prefix the saved block checkpoint would have matched. Never changes restore or save behavior. |

| `FIFI_Q36_MLX_DISK_DENSE_FFN` | off | Set to `1` with MLX device sizing enabled to stage the Qwen3.8 dense gate, up and down matrices one layer at a time. Decode and prefill charge the largest layer stage alongside resident weights and session memory. |

| `FIFI_Q36_MLX_FUSE_FINAL_PREFILL` | off | Set to `1` to include the pending prompt token in the last Qwen3.8 dense prefill batch and reuse its logits at the first decode step. Applies to single-sequence disk-staged FFNs when the enlarged batch fits in one forward. |
| `FIFI_MLX_EXPERT_READ_RUNS` | automatic | Group adjacent expert slice reads on the multi-row disk-backed paths in Flint, Flash-Next and Qwen3.6 MoE; each run covers exactly the selected experts. Automatic: on for each engine whose experts stream from disk (the value belongs to the engine, so a streaming engine does not change another in the same process). `prefill` forces it on, `0` or any other value off. Flint's legacy read policy and pipeline switches take precedence when set. |
| `FIFI_MLX_OVERLAP_EXPERT_READS` | automatic | Submit the independent shared expert to Metal before the same layer's exact routed weights are read on the CPU, on the disk-backed paths in Flint, Flash-Next and Qwen3.6 MoE. Automatic: on for each engine whose experts stream from disk, as above. `1` forces it on, `0` or any other value off. Flint's legacy pipeline switch takes precedence when set. |
| `FIFI_MLX_POSITIONED_READS` | automatic | Read local safetensors shard ranges at explicit offsets in Flint, Flash-Next and Qwen. Contiguous and vectored reads fill the existing buffers for the same validated ranges. Automatic: on for each engine that starts under a device budget (the experts may stream). `1` forces it on, `0` or any other value off. |

## CUDA

| Variable | Default | Accepted values | Meaning |
| --- | --- | --- | --- |
| `FIFI_CUDA_ATTN_PREFILL_ADAPT` | `0` | `0`, `1` | Experimental FP16 prefill attention selection for supported model geometries. `1` chooses a kernel using the current device's per-block shared-memory and thread limits; unset, `0` and unrecognized values retain the original launch path. Read once per process; restart to change it. The adaptive path is not yet qualified across RTX 20, 30, 40 and 50 series. See [CUDA FP16 prefill attention](configuration.md#cuda-fp16-prefill-attention). |
| `FIFI_CUDA_POISON_ALLOC` | off (switch) | Debug fill, on for `1`, `true` or `on`: every device allocation the engine hands out through the device allocator or the allocation cache — a fresh block and a reissued one alike — is first filled with `0xFF`, so a kernel that reads memory it never wrote sees the fill instead of a previous tenant's bytes (compute-sanitizer's initcheck cannot catch a recycled block, which counts as written). The fill streams in 64 MiB chunks and the armed hit settles the cache first; leave it off outside sanitizer legs and defect hunts. Read once per process; restart to change. |

| `FIFI_FLINT_MLX_EXPERT_CACHE_MIB` | off | positive MiB, `0` | Reserve per-layer unified-memory slots for packed experts in one-row Flint forwards with automatic device sizing and disk-backed weights. ## Bolt (Gemma4) on NVIDIA CUDA

| Variable | Default | Accepted values | Meaning |
| --- | --- | --- | --- |
| `FIFI_BOLT_ATTN_SPLIT` | on (switch) | `1`, `on`, `0`, `off` | Selects the split decode attention of the Bolt step: one partial and one combine launch per attention instead of the single-pass kernel. The split changes the summation order and matches the f64 reference within its tolerance. Measured: the full-attention call is 11.7 times faster at 30K depth, and served decode goes from 6.8 to 43 tok/s there with the greedy output unchanged over 96 tokens. `0` or `off` returns to the single-pass kernel. Any other value is refused at load. Read once per process. |
| `FIFI_BOLT_ATTN_SPLITS` | device-derived | `1` to `128` | Overrides the split count of the Bolt decode attention. Unset, the count is 32 scaled by the device query's multiprocessor count over the 82 it was tuned on, so the 82-SM card keeps 32 and a 20-SM card gets 8; a driver that reports no count keeps 32. The count changes the summation order, so a prefix entry written under another count is a different entry. Any other value is refused at load. Read once per process; restart to change. |

## Tests

These are read by `cargo test`, not by `enginesrv`. A test that needs recorded data finds each location by name: the environment variable first, then the same key in the JSON object `~/.config/fifi/test-paths.json`. The tests that read them skip when a location is unset, and fail instead when `FIFI_TEST_REQUIRE_DATA` is exactly `1`. A deliberate `#[ignore]`d run always fails on a missing value. The qualification, benchmark and oracle harnesses read further variables (`FLINT_QUAL_*`, `DT_*`, `FIFI_GRAPH_BENCH_*`, `FIFI_FLINT_*_ORACLE*`, `FLINT_PROBE_*`, the `*_CHILD` child-process fault harnesses and the like); those are inputs of the harnesses, not serving switches.

| Variable | Default | Meaning |
| --- | --- | --- |
| `FIFI_EXL3_SWEEP_LAYERS` | `12` | For the ignored `flint_shape_rate_latency` timing test of the EXL3 CPU kernel (random weights of the Flint expert shape at every stored rate): how many layers of six experts the rounds cycle through. `1` keeps the six experts cache resident; the default exceeds the caches. Run `cargo test --release --lib flint_shape_rate_latency -- --ignored --nocapture` from `engine/`. |
| `M3_LAYOUT_DIR` | unset | The frozen layout directory of the EXL3-versus-GGUF quality comparison. The two default tests that load it skip when it is unset; the ignored `m3_compare` test requires it. |
| `M3_COMPARE` | unset | For the ignored `m3_compare` test: `P1:<candidate dir>:<reference dir>` or `O1:<candidate dir>:<reference dir>`, the two recorded sidecar sets to score. Run `cargo test --lib m3_compare -- --ignored --nocapture` from `engine/`. |
| `M3_REGISTRATION` | unset (refused) | For `m3_compare`: `v6` or `v7`, the registration version whose rule scores the pair. There is no default: an unset or unknown value stops the test before any sidecar is read, and every verdict names its version (see `qualification/o1-gate-v7/`). |
