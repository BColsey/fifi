# Environment variables

Set these before starting `enginesrv`; the server reads them once at startup.
The API key variable is not listed here: its name comes from `api_key_env` in the [configuration file](configuration.md).

Two kinds of values appear below:

- A **switch** that is unset keeps its default. A switch that is set is on only for `1`, `true` or `on` (surrounding spaces and letter case are ignored); any other value turns it off.
- A variable with **accepted values** refuses startup when set to anything else, unless the table says otherwise.

## Build

| Variable | Default | Meaning |
| --- | --- | --- |
| `INFERENCE_CUDA_ARCHS` | `86` (`72` on aarch64) | Comma-separated GPU architectures for the CUDA kernels, for example `89` for RTX 40-series cards or `86,89` for both. Read by `cargo build --features native-cuda`. |

## Server

| Variable | Default | Meaning |
| --- | --- | --- |
| `ENGINESRV_WARM_TURNS` | on (switch) | With `prefix_reuse`, remember the last conversation's tokens so that the next turn only tokenizes its new messages. A request from another conversation replaces the memory. |
| `ENGINESRV_PREFIX_BLOCK_MATCH` | on (switch) | With `prefix_reuse`, also save one block checkpoint, cut at a multiple of `ENGINESRV_PREFIX_BLOCK_TOKENS` tokens just before the end of the conversation, so a prompt that changes only near its end can still reuse most of it. Used by engines that keep at least two saved prefixes. |
| `ENGINESRV_PREFIX_BLOCK_TOKENS` | 4,096 | Spacing of the cut points, in tokens. Values below 1 select the default. |
| `ENGINESRV_CACHE_USAGE` | on | Report reused prompt tokens in the API usage fields. Once set, only the exact values `1`, `true` and `on` keep it on. |
| `ENGINESRV_THINK_REPLAY` | on (switch) | Qwen3.6 only: keep the reasoning that clients resend with earlier assistant turns in the prompt. Off removes it for every engine. |
| `ENGINESRV_NOTICE_TOOLWRAP` | on (switch) | Qwen3.6 only, with think replay on: render system messages that follow an assistant turn as tool responses, so that the chat template keeps the reasoning of earlier tool-calling turns. |

## Qwen3.6 on NVIDIA CUDA

| Variable | Default | Accepted values | Meaning |
| --- | --- | --- | --- |
| `Q36_VERIFY_GGUF_SHA256` | `0` | `0`, `1` | `1` checks the model file's SHA-256 while it loads. |
| `Q36_CUDA_CHUNK_PREFILL` | on (chunked prefill) | `0`, `1` | `0` processes the prompt one token at a time, with the `q8` cache and with the default `f32` cache (FP16 storage). Checked on an EXL3 pack with both caches; a GGUF file with Q6_K weights never chunks. Unset or `1` leaves the chunk path on. |
| `Q36_CUDA_CHUNK_ROWS` | `1024` | `16`, `128`, `512`, `1024` | Largest prompt chunk of the `q8` cache when chunking is on. Ignored with the default `f32` cache (FP16 storage), whose chunks are 2,048 rows for the first 3,072 positions and 1,024 after that. |
| `Q36_CUDA_KV8_STAGE_CONTEXT` | `1` | `0`, `1` | `0` limits the FP16 attention staging buffer to 65,536 rows. |
| `Q36_CUDA_KV8_FIXED_ADMISSION` | `1` | `0`, `1` | `0` returns to the older way of choosing chunk sizes, which may pick smaller chunks or one token at a time. On a 24 GB card, use the 131K profile with it. The shrink ladder degrades the stage instead of refusing the boot within its reach — above 131,072 rows up to 48 MiB of headroom over the 32,768-row default stage (plus the existing 192 MiB wide fallback when a wide stage was offered and refused); at or below 131,072 rows it runs from the full-context stage down to the floor instead; it does not create free VRAM. The floor is max(8192, ceil(context / 128)) — 8192 everywhere shipped — and odd stages or halves that cross the floor stop the ladder earlier (at context 2,097,152 the floor is 16,384, a 32 MiB relief; at 131,071 the initial stage is odd so nothing shrinks). Measured on a 24 GiB card with a 1.2 GiB desktop, prefix reuse off (charges as the admission gate computes them: the max part charge and the 64 MiB spare minimum included): the unballasted 262144 profile misses the boot by 393.5 MiB at the 32768-row default stage and still 345.5 MiB at the 8192-row floor rung (exactly the 48 MiB the ladder relieves); with the shipped prefix profile (prefix reuse on) the flat device-prefix extra adds about 62.8 MiB (65,863,680 B, ledger extras_fixed) — 456.3 MiB at the default stage and 408.3 MiB at the floor, derived from the same prefix-off snapshot (a measured prefix-on refusal at a later snapshot missed by 383.7 MiB); how much the miss really is depends on how much VRAM the desktop holds at boot — the 262144 profile needs 393.5 MiB (prefix off; 456.3 MiB with the shipped prefix profile) more free VRAM than measured to boot at the default stage. Making 262K boot on such a card is a budget/profile decision, not a ladder behavior. |
| `Q36_CUDA_CPF_STAGE_128K` | `1` | `0`, `1` | Above 131,072 tokens, attention stages a 131,072-row buffer (256 MiB) when it fits. `0` starts from the 32,768-row buffer (64 MiB) and halves it whenever it is refused (also after a refused wide stage with the flag on), down to the floor max(8192, ceil(context / 128)) — where 8192 is the measured performance floor; halves that cross the floor stop the ladder earlier, and a snapshot too tight for every rung refuses with the original error. No effect at or below 131,072 tokens. |
| `Q36_CUDA_PINNED_PREFIX` | on | only `1` is on | Any other value keeps saved prefixes in pageable host memory and turns off the GPU copy. |
| `Q36_CUDA_STATE_ONLY_PREFIX` | on | only `1` is on | Any other value turns off the GPU copy of the newest prefix and keeps the pinned host copies. |
| `Q36_CUDA_PINNED_PREFIX_BYTES` | smaller of 3 slots and 8 GiB | byte count | Size of the pinned host pool for saved prefixes. `0` keeps none. |
| `Q36_CUDA_PAGED_DEVICE_FIRST` | `0` | `0`, `1` | With `kv_offload_host_bytes`: keep as much of the KV cache on the GPU as fits after a 1 GiB reserve. |
| `INFERENCE_CUDA_KV8_ATTN_V_PREFETCH` | `0` | only `1` is on | Experimental register-V decode attention: use the prefetch kernel variant, which holds the next key's code words in registers ahead of the dot chain. Read once at startup; only the exact value `1` turns it on, any other value or unset keeps the default kernel. Head dimension 256 only, and it needs the register-V KV8 decode attention path (the default with `kv_dtype: q8`); outputs are bitwise-equal to it. |

`Q36_CUDA_CHUNK_PREFILL=0` and `Q36_CUDA_KV8_STAGE_CONTEXT=0` also turn off `Q36_CUDA_KV8_FIXED_ADMISSION`.
With `tiered`, the pinned prefix pool is off unless `Q36_CUDA_PINNED_PREFIX=1` is set.

On NVIDIA CUDA:

| Variable | Default | Meaning |
| --- | --- | --- |
| `FIFI_FLINT_CUDA_ALLOC_CACHE` | on (switch) | Reuse small GPU allocations (at most 1 MiB each, 16 MiB and 256 entries in total). The cache is emptied after each request. |
| `FIFI_FLINT_CUDA_ALLOC_LAZY_RETURN` | off (switch) | With the allocation cache on, let a returned GPU block go idle without a device-wide synchronize while the engine has a single GPU stream; the next user of the block is ordered behind the old one by that stream. A host-synchronous write into a cached block, and the creation of a second stream, still synchronize first (once, and only if blocks went idle since the last synchronize). Output is unchanged. A sticky asynchronous kernel error is then first seen at that next synchronize rather than where the block was dropped. Accepted values are `1`, `true` and `on`; any other value, including empty and non-UTF-8, leaves it off. Read once; restart to change. Needs `FIFI_FLINT_CUDA_ALLOC_CACHE` on, which is the default. The startup line reports `alloc_return=lazy` only when it is armed. |
| `FIFI_FLINT_CUDA_EXPERT_CACHE` | unset (auto) | Where the routed experts of the MoE layers live. Unset: every expert stays on the GPU when `context_limit` fits that way, exactly as before. A longer context keeps all 256 experts of every layer in one page-locked host buffer (about 18 GiB for the EXL3 4.0 pack) and only as many per layer on the GPU as the free GPU memory leaves room for, after the other weights, the KV cache for `context_limit`, the work reserve and headroom. An expert that is not on the GPU is copied in from the host buffer and replaces the least recently used expert that the current prompt chunk or decode step does not use. Output is the same either way, because the weights and kernels are the same; fewer experts on the GPU cost a copy per miss. `1`, `true` or `on` always uses the host buffer, and then also leaves 160 MiB of the free GPU memory unused for the choice of all 256. `0`, `false` or `off` keeps every expert on the GPU and refuses a context that does not fit, naming the largest one that does; this is the rollback. Any other value, including empty, refuses startup. With the host buffer in use, startup is refused, with no fallback to pageable memory, unless free host memory covers the buffer plus a floor of the larger of 8 GiB and a tenth of physical memory, and unless the count is at least 6 times `prefill_chunk_size`; the refusal names the largest context that fits without the buffer. The load line reports `expert_slots=` and `bank=auto`, `bank=forced` or `bank=override` when fewer than 256 experts per layer are on the GPU. When a request finishes on such a bank, one line goes to standard error: `Flint expert bank:` followed by `slots`, `prefill_misses`, `decode_tokens`, `decode_misses`, `decode_misses_per_token` and `copied_bytes`; the decode figures include the step that feeds the prompt's last token. Read once at load; restart to change. Rollback: `FIFI_FLINT_CUDA_EXPERT_CACHE=0`. The `cpu_moe_*` keys of the `flint` object (see configuration.md) compute some experts on the CPU from this host buffer instead of copying them in. |
| `FIFI_FLINT_CUDA_EXPERT_SLOTS` | largest that fits | Routed experts per layer kept on the GPU, a whole number from 1 to 256. Setting it asks for the host buffer, even when every expert would fit on the GPU; with `FIFI_FLINT_CUDA_EXPERT_CACHE=0` it is refused. A count that does not fit the free GPU memory, or is below 6 times `prefill_chunk_size`, refuses startup and names the bytes that remain; the engine never shrinks it silently. Write plain digits: a sign, a leading zero or a space refuses startup; empty counts as unset. Read once at load; restart to change. |
| `FIFI_FLINT_DEVICE_PICKS` | off (switch) | Keep the router's expert ids on the GPU during single-row decode steps over a load with every expert resident: the layer no longer reads the ids back or waits for them, and the routed gate, up and down projections run as launches that pick each expert by its id on the device. The output is the same bytes as the host-routed path. A layer runs the host-routed path instead, and one line naming the reason goes to standard error (once per layer), when the load keeps experts in the host buffer (`FIFI_FLINT_CUDA_EXPERT_CACHE` banked; one line for the whole load), when experts are computed on the CPU (`cpu_moe_*` keys), when the experts of the layer differ in shape or rate, when the three projections of an expert do not sit at one common offset, or when the experts of the layer span 4 GiB or more. Prompt chunks of more than one row always run the host-routed path. Accepted values are `1`, `true` and `on` (surrounding space and letter case are ignored); any other value, including empty and non-UTF-8, leaves it off. Read once; restart to change. The startup line reports `Flint device picks: on` when it is armed. |
| `FIFI_FLINT_LATE_HEALTH` | on (switch) | Check the model output for non-finite values on the GPU. |
| `FIFI_FLINT_TOKEN_HEALTH` | on (default; `0` rolls back) | Token-end health gate for single-row calls (decode and one-row prefill tails): unless it is turned off, armed calls clear the 49x2-word status ring (one 392 B write) at token start, park the per-frame FFN health words in it, skip the per-layer attention `Group::check`, and at the token end (before the head, sampling and KV append commits) do one sync and two ring reads replacing the per-frame status reads and their event syncs, reporting the earliest fault in execution order; error classes are unchanged and aborts keep the original refusal message unless a ring fault ran strictly earlier. Multi-row prefill chunks keep the existing per-frame path. A fault in one layer therefore surfaces once per token, at the token end, with the same error text the per-frame check gives for that class (a model-output refusal for non-finite or out-of-range values, a backend error for a failed launch) and no token is sampled or committed from that step; the layer that faulted is not named earlier than the token end. After a fault that leaves finite garbage, the later layers of that token still run, including bank copies and CPU-expert hot-set updates; those only reorder the least-recently-used and hot-set bookkeeping and are recovered when the session resets. Unset, `1`, `true` and `on` keep it on; any other value, including empty and non-UTF-8, turns it off. Read once at session construction; restart to change. Rollback: `FIFI_FLINT_TOKEN_HEALTH=0` and restart. |
| `FIFI_FLINT_CUDA_PACKED_POINTWISE` | on (switch) | Packed BF16 element-wise kernels for the routed expert loop: one fused pass over the pick rows instead of a launch per group, bit-identical output by sweep and served text parity, faster end to end (TTFT -23.9 pct and decode throughput +13.1 pct on a 4000-token prompt on the RTX 3090, restart-per-arm pair). Any other set value, including empty and non-UTF-8, rolls back to the per-group loop. Read once; restart to change. |
| `FIFI_FLINT_CUDA_Q8_TILED` | on (switch) | Tiled q8 KV attention kernel: routes q8-KV attention for prompt rows AND decode steps through the tiled kernel (the legacy rollback path runs the same rows through the prefill-shaped call; f16 caches always use the f16 kernel). Read once at the first Flint CUDA engine load using the q8 KV profile; restart to change. Rollback: set `FIFI_FLINT_CUDA_Q8_TILED=0`. Measured on the RTX 3090 (sm_86) only; sm_72 builds are compile-only coverage. Output is NOT bit-identical to the rollback kernel (different reduction order within the 2^-14-class bound), so served text can differ from the rollback configuration. Teacher-forced against f16 KV on 8,448 repository-source positions (11 segments, depths 257 to 8,192 tokens, one model, Rust source only): mean per-position KL is 0.254 nats on the legacy kernel and 0.266 nats on the tiled kernel - pooled +4.8 pct (95 pct CI -6.9 to +18.0), within the pre-set x1.10 bar as a point estimate; not shown equivalent; short-context positions +12.9 pct, mid/long about -11 pct. | `FIFI_FLINT_CUDA_FUSED_PUBLISH` | on (switch) | Producer fusion for the CUDA walk: the EXL3 projection, grouped projection, row-multiply and row-add kernels store the BF16-rounded value themselves, with the same rounding and the same non-finite check and flag as the separate publish kernel, so the separate publish launch is skipped at those sites. | `FIFI_FLINT_CUDA_KV_DEVICE_F16` | on (default; `0` rolls back) | Run the KV cache row acceptance guard on the GPU instead of reading each layer's new K and V rows back to the host. On the f16 KV profile the GPU also writes the accepted half-precision rows into the cache, so the host read and the 1,024-byte upload per row (98 pairs per decoded token) are not issued; on the q8 profile the GPU append is unchanged and only the guard moves. A row is accepted when it is finite, has its low 16 bits clear and converts to a finite f16 (round to nearest even), the same rule and the same stored bits as the host path; a rejected row fails the token with the same error, checked once per token before sampling (once per prompt piece in layer-major prefill). Unset, `1`, `true` and `on` keep it on; any other value, including empty and non-UTF-8, turns it off. Read once at the first Flint CUDA engine load; restart to change. Rollback: `FIFI_FLINT_CUDA_KV_DEVICE_F16=0`. |
